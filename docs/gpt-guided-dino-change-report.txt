GPT 관찰 기반 DINO 추가 탐지 개편 (2026-11-02)


기존: GPT·OCR·공통 목록 DINO를 병렬 실행하고 객체 crop을 GPT로 검토했다. GPT가 관찰한 링 조명·가구·난간 등이 공통 목록에 없으면 좌표가 없었다.
변경: 전체 이미지 GPT 응답에 후보별 영어 detectionKeywords를 추가했다. 새로운 GPT API 호출로 키워드를 번역하지 않고 기존 이미지 분석 응답에서 함께 받는다. 후보당 최대 3개 구체적 객체 표현이며 추상적 관찰은 빈 배열이다.

DINO에서 찾는 객체
건물 외관, 입구, 발코니, 계단
조형물, 벽화, 분수, 탑
매장 로고
호수, 해안선, 절벽, 산

파이프라인:
GPT(관찰+영어 검색어) / OCR / 기본 DINO 병렬 실행
→ GPT와 기본 DINO 완료
→ 기존 동일 레이블 탐지에 연결 제안 생성
→ 나머지 검색어를 합쳐 DINO 추가 탐지 최대 1회
→ 기본·추가 객체를 crop으로 GPT 검토
→ 검증된 연결 제안만 GPT 후보 좌표로 표시
→ 주요 단서·배경 비교 자료·판단 보류·제외 보존.
OCR Fusion은 기존처럼 독립적으로 진행한다. 연결 제안은 실제 공간 관계 확인이나 정답이 아니다.

추가 검색: 최대 12개 고유 검색어, 합계 400자. 초과 대상은 이번 탐지에서 생략되므로 좌표 없이 남을 수 있다. 기본 탐지에 동일 레이블이 있으면 추가 검색하지 않고 기존 영역을 검토한다. OCR 연결이 이미 확인된 후보는 제외한다. OCR Fusion과의 실행 순서에 따라 일부 중복 검색이 남을 수 있다.
여러 링 조명은 각각 탐지 ID와 bbox로 보존하며 하나의 GPT 관찰에 여러 영역을 연결할 수 있다. GPT가 crop에서 확인한 객체 대응만 연결하며 개수·배치·창밖 관계까지 검증했다고 간주하지 않는다. 레이블이 검색어와 정확히 일치하지 않으면 자동 연결 제안을 하지 않는 보수적 구현이다.

저장: grounding.supplemental에 검색어·후보 인덱스·완료/생략 상태를 기록한다. 탐지별 candidateIndexes는 연결 제안이다. 실제 Fusion relatedCandidateIndexes는 crop 검토 결과다. 탐지 결과 저장 후 검토가 실패하면 재시도 시 추가 탐지를 반복하지 않는다. 탐지 자체가 실패하면 명시적 재시도에서 재실행할 수 있다.

프롬프트 버전: feature-discovery-v4-keywords / object-fusion-v6-guided. 모델은 기존 설정 유지. 영어 지시·한국어 설명을 사용한다. 이전 결과는 자동 재분석하지 않으며 검색어가 없는 이전 기록은 추가 탐지를 생략한다.

비용과 지연: GPT 호출 횟수는 유지하나 검색어 출력과 추가 crop 검토로 토큰이 늘 수 있다. 로컬 DINO 추가 실행으로 시간이 늘어난다. 유료 호출 및 실제 이미지 추론은 이번 작업에서 실행하지 않았다. 실제 정확도 향상은 미검증이다.

제약: 키워드 생성 누락·환각, 탐지 오차, 정확 레이블 연결의 누락 가능성이 있다. 단일 객체 검증으로 전체 배치 일치를 증명하지 않는다. 누적 분석이나 실제 위치 추론은 추가하지 않았다.
