꼭꼭 단독 분석 개편 보고서
작성일: 2026-11-02

1. 이번 변경의 목적

단독 분석은 사진 한 장에서 관찰되는 단서를 추출하고, 직접적인 위치 식별 정보는 경고하고, 간접적인 정보는 안내하면서 저장한다. 과거 사진 검색, GPS 그룹화, 단서 간 조합, 반복 노출 점수 계산은 이번 작업에 포함하지 않는다.

2. 기존 방식과 변경 방식

기존에는 GPT가 “외부 정보와 결합했을 때 위치를 좁히는 데 유용한가”를 기준으로 useful / not_useful / uncertain을 판단했다. OCR·객체 검토의 useful에는 low / medium / high가 필수였고, 전체 사진 분석은 반환한 모든 후보에 위험도가 필요했다. 직접·간접 단서 구분은 없었다.

이제 useful은 “직접 또는 간접 단서로 보존할 관찰 근거가 있음”을 뜻한다. 지점명 없는 브랜드와 일반적인 고정 배경도 누적 분석용 관찰로 남길 수 있다. not_useful은 탐지 오류·무관한 내용, uncertain은 관찰·판독·관련성 판단 부족이다.

GPT는 개별 관찰, 판단, 적용 규칙 ID, 관찰 확실성, 근거와 한계를 반환한다. 위험도를 직접 출력하지 않는다. 서버가 버전 관리된 규칙표에서 직접/간접 역할, 식별 범위 추정, 등급, 표시 방식을 계산한다.

입력 지시문은 세 호출 모두 영어다. 사용자에게 보여주는 설명과 관찰은 계속 한국어로 출력하도록 했다.

3. 처리 예시

가. 지점명 없는 프랜차이즈 간판
기존: GPT가 useful 또는 not_useful로 판단했고, not_useful이면 기본 화면에서 제외될 수 있었다.
변경: 브랜드만 확인된 경우 chain_brand 규칙, indirect, low, notice. 지점과 도시를 단정하지 않고 간접 단서로 저장한다.

나. 도로명과 건물 번호가 선명한 고정 주소판
변경: address_number 규칙, direct, high, warning. 단서가 특정 장소 식별 정보를 담는다는 규칙상 평가이지, 실제 위치나 거주지를 검증했다는 의미는 아니다.

다. 흐릿하거나 일부만 읽히는 이름
변경: 읽힌 부분만 기록한다. partial 또는 unverifiable 관찰, uncertain 판단에는 위험도 null을 사용하며 판단 보류로 표시한다. 없는 글자를 채우지 않는다.

라. 일반적인 창문·출입구·외벽
변경: standard_fixed_structure 규칙에 해당하는 관찰은 indirect, low로 저장한다. 지금 위치를 알아낼 수 없다는 이유만으로 제외하지 않는다.

마. 문자가 포함된 간판·메뉴판의 객체 crop
기존: 문자 담당은 OCR이라는 이유로 객체 검토에서 not_useful을 강제했다.
변경: 문자를 읽는 역할은 OCR에 유지한다. 간판의 프레임·형태·설치 구조 등 독립적인 비문자 관찰은 간접 단서로 보존할 수 있다. 비문자 채널이 문자 기반 직접 식별 규칙을 선택하면 서버가 거부한다.

4. 규칙 적용 범위와 PDF 대비 보완

PDF 1장의 개별 단서 평가 원칙과 2장의 단서별 사례를 바탕으로 21개 규칙을 구현했다. 3장의 조합 규칙은 적용하지 않는다. 한 간판의 인접한 OCR 글자들을 연결해 브랜드+지점명 또는 도로명+번호를 읽는 작업은 하나의 식별자 복원으로 허용한다. 서로 다른 물체의 단서를 결합해 위험도를 높이지 않는다.

범위 대응: single_place -> high, few_places_or_neighborhood -> medium, city_district/country_region -> low, unknown -> null. 현재 보수적인 개별 규칙표에는 city_district를 자동 부여하는 규칙이 없다. 위치와 관련된 별도 근거 없이 도시를 가정하지 않기 때문이다.

규칙상 범위는 실제 후보 개수나 실제 지도 검색 결과가 아니다. 모든 새 평가에 scopeVerified=false를 저장한다. 모델이 규칙을 잘못 선택하면 등급도 잘못될 수 있으므로 실제 사진 검증이 필요하다.

비체인 상호·기관명·역명·정류장명이 선명해도 “유일한 장소”라고 확정하지 않고 named_identifier의 중간 등급으로 보수적으로 평가한다. 부분 이름은 범위 판단 불가로 둔다. 독특한 구조물·조형물·벽화·자연 지형도 유일성을 단정하지 않는다. 구체적 외형을 기록하고 중간 수준의 가설적 등급으로 제한한다.

지점명 없는 반복 브랜드, 단지명 없는 동 번호, 운영 범위를 확인하지 않은 노선 번호는 그 자체로 특정 도시를 좁혔다고 해석하지 않는다. 매장 수가 적어 보인다는 이유만으로 별도 승격하지 않는다. 대표 전화번호인지 지점 전화번호인지 확인되지 않은 연락처는 직접 식별 정보 후보로 남기되 범위·등급은 unknown/null이다. 이동 가능한 브랜드 물건은 매장 위치의 증거로 확정하지 않는다.

5. 저장 형식

기존 modelRisk 필드는 호환을 위해 유지하되 새 분석에서는 GPT가 직접 정한 값이 아니라 서버 규칙으로 계산된 값이다. GPT 원문(rawOutputText)은 계산 전 응답 그대로 보존한다.

새 assessment에는 다음이 저장된다.
- policyVersion: single-cue-v1
- ruleId: 적용 규칙
- certainty: clear / partial / unverifiable
- evidence: 관찰 근거
- limitation: 판정 한계
- role: direct / indirect / unknown / none
- estimatedScope: 규칙에 따른 범위 추정
- scopeVerified: false
- displayMode: warning / notice / review / excluded

모델 원문과 사람 수정은 분리한다. 사람도 근거가 부족하면 등급을 억지로 선택하지 않고 ‘평가 보류’를 명시한 뒤 이유를 남길 수 있다. 단순 미검토와 의도적인 평가 보류는 별도 값으로 구분한다.

기존 OCR·객체 원문, bbox, 제외·불확실 결과는 계속 저장된다. 새 단서 판단이 불확실하면 기본 검토 화면에서도 확인할 수 있다. 탐지와 무관하다고 판단한 항목은 제외 항목에서 확인·복원할 수 있다.

6. 파이프라인 전후

기존:
사진 전처리
-> 전체 사진 GPT / PaddleOCR / Grounding DINO 병렬 실행
-> GPT+OCR 완료 후 OCR GPT 검토
-> GPT+DINO 완료 후 객체 crop GPT 검토
-> 유용성 및 모델 위험도 판단
-> useful 중심 카드 표시와 사람 검토·저장

변경:
사진 전처리
-> 전체 사진 GPT / PaddleOCR / Grounding DINO 병렬 실행
-> GPT+OCR 완료 후 OCR GPT 검토
-> GPT+DINO 완료 후 객체 crop GPT 검토
-> GPT가 개별 관찰·판단·규칙 ID·확실성 반환
-> 서버가 직접/간접 역할·범위·등급·표시 방식 결정
-> 직접 단서 경고 / 간접 단서 안내 / 불확실 결과 검토 표시
-> 원문·판정 근거·bbox 보존 및 사람 검토·저장

실행 순서와 의존 관계는 바꾸지 않았다. 기존 전체 사진 GPT 호출도 유지했다. 객체 crop 검토는 이전처럼 전체 장면·기존 GPT 관찰·OCR 원문을 받지 않는다. 추가 GPT 호출은 없다. 전체 사진 분석, OCR 검토, 객체 검토의 최대 세 번 구조를 유지한다. 프롬프트 길이가 늘었으므로 입력 토큰은 증가할 수 있으며 실제 비용은 측정하지 않았다.

PaddleOCR 설정, DINO 탐지 문구·임계값·모델, 이미지 전처리, crop 생성, bbox 계산 방법은 변경하지 않았다. 현재 PoC bbox는 정규화된 [x1,y1,x2,y2] 형식이며, ERD 초안의 x/y/width/height 방식으로 바꾸지 않았다.

GPS를 통한 사진 그룹화와 과거 사진의 단서 비교, 누적 점수 계산은 아직 구현하지 않았다. 사진 전체의 검증된 0~100 점수도 새로 만들지 않았다.

7. 이전 기록과 API

새 프롬프트 버전은 feature-discovery-v3-single, ocr-fusion-v2-single, object-fusion-v4-single이다. 기존 프롬프트 버전과 과거 위험도 정의를 계속 읽을 수 있다. 과거 데이터를 자동 재평가하거나 API로 다시 전송하지 않는다. 과거 카드에는 이전 기준이며 직접/간접 구분이 없다고 표시한다. 이미 저장된 결과는 새 기준으로 자동 바뀌지 않으므로 새 사진 분석에서 변경을 확인해야 한다.

Node 검사 접수·조회 경로는 유지한다. riskFactors의 기존 필드는 유지하고 새 결과에 assessment와 decision을 추가했다. riskFactors 배열에는 직접 단서뿐 아니라 간접·판단 보류도 포함될 수 있으므로 소비자는 assessment.displayMode를 기준으로 표시해야 한다. 기존 riskSummary.score는 null이며 반복 노출 결과는 미구현 상태 그대로다.

Spring 서버와 별도의 앱 프론트는 이번에 수정하지 않았다. 해당 서버가 새 필드를 DTO에서 전달하는지와 앱이 안내/경고를 구분하는지는 후속 연동 확인이 필요하다. PoC 자체 검토 화면에는 반영했다.

8. 검증

검증 결과:
- lint: 통과, 경고 없음.
- typecheck: 통과.
- 단독 분석 새 응답/규칙/간접 안내/불확실 등급/원문 보존: 모의 검증 통과.
- OCR Fusion·객체 Fusion·crop 좌표·전체 ID 보존·기존 저장 기록 두 개 읽기: 통과.
- 업로드·저장·삭제·사람 수정·병렬 처리·검사 API·bbox 카드 정적 렌더: 회귀 검증 통과.
- 실제 원본 폴더의 build: OneDrive 경로 .next 하위 디렉터리 생성 중 EPERM 발생.
- 별도 검증 폴더의 build: 컴파일·TypeScript·정적 페이지 생성·빌드 완료 모두 통과. 단일 워커 모드를 사용했으며, 검증본과 현재 src 파일 66개의 SHA-256 일치를 확인했다.
- 최초 임시 폴더에서 파일 삭제 회귀 검증의 rename EPERM이 발생했다. 작업 폴더의 별도 임시 디렉터리로 실행 위치를 바꾸자 해당 검증이 통과했다.
- 실제 브라우저 클릭과 실제 GPT 출력 품질 검증은 수행하지 않았다. 실제 OpenAI API 호출과 실제 이미지 전송은 수행하지 않았다. 모의 응답과 합성 이미지로 계약·저장·화면을 검사했으므로 실제 GPT 분류 정확도를 검증한 것은 아니다.
